# Sensor choice & ADC reference — измерения

## 12.09.26 — Stage A sanity check (MPX5700AP, экземпляр из коробки старых деталей)

**Сборка:** MPX5700AP на макетной плате, Vout → AtomS3R G5, GND и Vcc — через
рейки макетки. Без делителя/ОУ/фильтра между датчиком и АЦП (README часть 2).

**Найденные и исправленные проблемы по пути:**
- Нестабильный контакт на рейке GND (прозвонка показывала то OL, то плавающие
  значения) — почини­ли переносом на другую пару отверстий/проверкой рейки,
  довели до стабильных ~0.2–0.3 Ом.
- Датчик стоял **не той стороной** (ножки перепутаны местами) — из-за этого
  Vout был заниженным (~0.47В) и не реагировал на давление вообще. После
  переворота — датчик сразу заработал.

**Итоговые измерения (после исправлений, датчик на атмосфере, USB подключён):**

| Величина | Значение |
| :--- | :--- |
| Vcc на датчике (мультиметр) | 5.00 В |
| Vout на атмосфере (мультиметр) | **0.85 В** — совпадает с ожиданием README |
| ADC raw (усреднено, наивная формула 3.3В/4095) | ~941 |
| ADC volts (наивная формула `raw × 3.3/4095`) | ~0.758 В |
| Расхождение ADC vs мультиметр | **~11%** — больше целевых 2% |

**Вывод:** расхождение стабильно повторилось на двух независимых замерах (до и
после переворота датчика, в разных абсолютных точках — ~0.47/0.42В и
0.85/0.758В дают то же самое соотношение ~11%), значит это не шум и не плохой
контакт, а систематическая ошибка допущения "опорное АЦП = 3.3В ровно".

**Оценка реального опорного напряжения АЦП:**
```
V_ref_эффективное = 3.3 × (0.85 / 0.758) ≈ 3.70 В
```

Использовано в `firmware/src/sensor.cpp` (`adcReferenceVolts()`) вместо
номинальных 3.3В.

**Функциональная проверка:** датчик реагирует на приложенное давление (палец на
порту) — выход растёт/падает предсказуемо. Электрическая целостность всех трёх
проводов (Vout, GND, Vcc) подтверждена мультиметром (<1 Ом на землю/сигнал,
честные 5.00В на питании).

**Дальше:** после прошивки `firmware/` — перепроверить итоговое совпадение
ADC/мультиметр с новым опорным (цель — ≤2%), записать результат ниже.

## 13.09.26 — проверка ADC vs мультиметр с V_ref=3.70В (README часть 2, требование ≤2%)

**Сборка:** та же (датчик на атмосфере, USB подключён, полная прошивка
`firmware/`, порт COM6, 115200 бод), давление на экране показывает
относительное значение (обнулено при старте от атмосферного baseline),
поэтому для проверки использовано сырое поле `"adc"` из JSON-телеметрии, а
не откалиброванное `"p"`.

**Мультиметр (Vout датчика относительно GND):** 0.85 В

**ADC:** 14 подряд идущих строк телеметрии, значения `adc`:
945, 946, 947, 946, 939, 951, 946, 946, 939, 946, 945, 945, 949, 943
— среднее ≈ 945.2 (разброс 939–951, т.е. 12 LSB пик-пик, насос выключен —
пригодится позже для замера шума).

**Перевод в вольты** (`вольты = ADC × V_ref / 4095`):
```
V_ref = 3.70 В (измеренное опорное, см. выше):
  945.2 × 3.70 / 4095 ≈ 0.854 В
  разница с мультиметром: |0.854 - 0.85| / 0.85 ≈ 0.5%   → ПРОШЛО (≤2%)

для сравнения, номинальные 3.3 В (старое допущение):
  945.2 × 3.30 / 4095 ≈ 0.762 В
  разница с мультиметром: ≈ 10.4%                          → не прошло бы
```

**Вывод:** требование README части 2 (ADC в пределах 2% от мультиметра)
выполнено с измеренным V_ref = 3.70 В. Подтверждает, что замена номинала
3.3В → 3.70В в `firmware/src/sensor.cpp` (`adcReferenceVolts()`) была
правильным решением, а не разовой случайностью на старых данных.

## Па на шаг АЦП (MPX5700AP, с измеренным V_ref)

Чистый расчёт по передаточной функции датчика (README часть 2:
`Vout = Vcc·(0.0012858·P + 0.04)`) и измеренному опорному АЦП, без нового
железа — можно посчитать сразу:

```
dP/dVout = 1 / (Vcc · slope) = 1 / (5 × 0.0012858) ≈ 155.55 кПа/В

Шаг АЦП (номинал 3.3В, как в README): 3.3/4095 × 155.55 ≈ 0.1253 кПа ≈ 125 Па/шаг
Шаг АЦП (измеренный V_ref = 3.70В):   3.70/4095 × 155.55 ≈ 0.1405 кПа ≈ 141 Па/шаг
```

**Вывод:** с реальным (более высоким, чем номинал) опорным напряжением
разрешение получается **хуже**, чем в номинальном допущении README (~141
Па/шаг вместо ~125 Па/шаг) — на ~13% грубее. Это отдельный аргумент к части
1 (выбор датчика): если понадобится точность лучше текущей, придётся либо
подтянуть опорное напряжение ближе к номиналу аппаратно, либо взять датчик
с более узкой шкалой (см. TODO ниже).

## 13.09.26 — шум в LSB, pump выключен vs pump включён (README часть 2)

**Сборка:** трубка от собственного (не ACU2-B) MG400 pump box подключена
напрямую в штуцер датчика (без тройника, без присоски/стекла — по совету
преподавателя, т.к. для шумового теста удержание вакуума не нужно, только
факт работы насоса).

**Первая попытка (не получилась, зафиксировано как есть):** насос запущен
через HTTP API `mg400-base` (`POST /api/pump {"mode":"suck"}`, DO2=suck по
умолчанию пакета). За 3 секунды среднее ADC почти не изменилось (941.7 →
941.5, атмосферное давление), хотя команда прошла без ошибки
(`errid:0, digital_out:2`). Вероятная причина: неплотное соединение
трубки или неверное предположение о DO-линии (в документации `mg400-base`
прямо сказано, что DO2=suck/DO1=blow — это догадка из чужой установки,
нужно проверять по факту). Не пересчитывали дальше — см. вторую попытку.

**Вторая попытка (успешная): физическая кнопка вакуума на коробке.**
Вместо API команду дал человек — нажал кнопку вакуума на самой коробке,
пока велась запись Serial-телеметрии (10 с окно).

| Состояние | n | среднее ADC | давление (отн. атмосферы) | шум (std) | min–max |
| :--- | ---: | ---: | ---: | ---: | :--- |
| До нажатия (атмосфера, "pump выкл") | 272 | 941.6 | ≈ 0 кПа | **4.84 LSB** | 930–954 |
| После нажатия (вакуум держится) | 401 | 361.1 | **≈ -81.7 кПа** | **3.68 LSB** | 349–372 |

Переход от атмосферы до почти финального значения — **~190 мс**, резкий
чистый скачок без промежуточных ступенек (в отличие от первой неудачной
попытки).

**Вывод и нюанс:** -81.7 кПа хорошо сходится с ранее измеренными
holding-curve результатами части 4 (napp klaasil ≈ -83 кПа, voolik korgiga
≈ -83.3 кПа) — подтверждает, что на этот раз соединение было герметичным.
Шум оказался НИЖЕ во время удержания вакуума (3.68 LSB), чем в состоянии
покоя (4.84 LSB) — это не противоречие, а следствие механики коробки: как
и в случае с заводским ACU2-B (часть 3), клапан держит вакуум пассивно
после достижения цели, мотор насоса не крутится постоянно. То есть это
сравнение "атмосфера / насос неактивен" против "вакуум удержан / насос
тоже неактивен", а не буквально "мотор работает". Настоящий шум
*активно работающего* мотора виден только в те ~190 мс самого перехода —
слишком короткое окно для отдельной статистики; если для защиты
понадобится именно шум при активной работе мотора, нужен более длинный
непрерывный цикл откачки (например, зафиксировать кнопку нажатой дольше
или воспроизвести это на менее герметичной системе, чтобы мотор не
останавливался).

## 13.09.26 — Falstad-схема: датчик → ADC со своим источником шума

**Осциллограф не был доступен в этой сессии** — спектр с подписанными
пиками (мотор насоса, сервоприводы MG400, USB-питание, 50 Гц) осознанно
пропущен, README-требование по этому пункту **не выполнено**. Вместо
этого собрана только Falstad-симуляция (ниже), без реального
спектрального подтверждения.

**Что сделано:** взяли стартовую схему из README (Andur 0,2–5V → ADC
muundur 0–3,3V), вставили последовательно между источником-датчиком и
входом ADC-модели источник шума (AC, `Voltage Source (2-terminal)`):

- **Амплитуда: 4.4 мВ** — взято из реально измеренного шума покоя
  (baseline atmosphere, замер выше: std ≈ 4.84 LSB × 3.70В/4095 ≈ 4.4 мВ).
- **Частота: 50 Гц** — **предположение, НЕ подтверждено экспериментально**
  (типичная сетевая наводка, но без осциллографа нельзя сказать, что
  реальный шум датчика действительно на этой частоте — это просто
  правдоподобная заглушка).
- DC offset: 0, Phase: 0, Internal resistance: 0.

**Результат симуляции:** на выходе ADC-модели (осциллограф "output")
видна квадратная волна (обрезание сигнала 0,2–5В датчика в диапазон
0–3,3В) с лёгкой рябью 50 Гц поверх плоских участков — качественно похоже
на то, что ожидается от наложенного шума, но это **подтверждает только
что модель настроена так, как мы её настроили** (амплитуда взята из
нашего же замера), а не независимая проверка реального шума датчика.
